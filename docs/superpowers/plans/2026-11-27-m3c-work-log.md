# Milestone 3c: Work Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show each turn's tool work the way T3 Code does. A settled turn folds its work under its prompt as "N秒作業しました", groups consecutive calls in one sentence, and opens into each call's command, output, exit code, or diff.

**Architecture:**

- **Core** (`OhMyOpenClawCore`):
  - `ToolActivityClassifier` is the only place that knows tool names.
  - `ToolDiff` parses diffs.
  - `WorkLogProjection` turns a `chat.history` page and its `activity` items into a `WorkLogPage`, keyed by the transcript record ids that `ConversationStore.parseMessages` produces.
- **Platform** (`OhMyOpenClawPlatform`): `WorkDuration` and `WorkLogCopy` hold the Japanese copy, and `Timeline` builds turns, folds, and groups.
- **State:** `AppModel` keeps one `WorkLogPage` per thread and physical session, in memory only, rebuilt on every history page and merged with older pages.
- **Views:** `TimelineItemView`, `WorkFoldRow`, `WorkGroupRow`, `WorkEntryRow`, and `DiffLinesView`.

The design comes from the M3b research (OpenClaw at `b1d355f`, T3 Code at `60375a56`) and its critique. Live tool output (the `agent` and `session.tool` reducer) is out of scope here.

**Tech Stack:** Swift 6.4, SwiftUI, Swift Testing, XCTest UI tests.

## Tasks

### Task 1: `ToolActivityClassifier` (Core, TDD)

- **Canonical names:**
  - strip `mcp__openclaw__` and `mcp_openclaw_`
  - unwrap `dispatch_action` and `tool_call` through `args.id`
  - lowercase
- **Kinds:** command, read, edit, write, search, fetch, subagent, and other.
  - A string `command` argument makes any tool a command.
  - A failed sub-agent counts as other.
- **Summary:** the collapsed command, the path, the pattern or query, the URL, or the task's first line, then the activity meta.
- **Hint:** the running-turn hint switches to `indicatesSearching`, and only a tool `result` ends it, since OpenClaw has no tool `end` or `error` phase.

### Task 2: `ToolDiff` (Core, TDD)

- **Numbered history diffs:** `<sign><padded number> <text>`, with elided rows of spaces and `...`.
- **`apply_patch` envelopes:** Update, Add, Delete, and Move.
- **Per-file unified diffs:** as Codex reports them.
- **Stats:**
  - A truncated diff has no stat.
  - A runtime-provided stat wins.
  - Display is clipped at 400 lines.

### Task 3: `WorkLogProjection` (Core, TDD)

- **Pairing:** calls pair with results by turn, run, and call id, falling back to the call id alone.
  - Result records and result blocks (Claude CLI `tool_result`) both count.
  - An orphan result anchors at itself.
- **State:**
  - With no activity, `isError` or a shell's non-zero exit code means failed, and a result means completed. A call with no result is unknown.
  - Activity items set the state and title. The result record's item is checked first, then the call record's.
  - An `unpairedCall` item is unknown.
  - When a record's activity list omits a call, the call is routine and hidden.
- **Run outcomes:** read from `run-failed-before-reply` rows, even though the transcript hides them.
- **Turn starts:**
  - Turns start at prompts and at `turnBoundary` rows without a continuation.
  - Assistant rows with a `senderSession` also start turns.
  - Steers, human-addressed notes, tool-result carriers, and continuations do not.
- **Times:** `recordTimestampMs` gives record times. Oversized result placeholders keep no output.

### Task 4: Copy (Platform, TDD)

- **Durations:** `WorkDuration.format` ports T3 Code's `formatDuration` to Japanese.
- **`WorkLogCopy.sentence`:**
  - It keeps the two most telling kinds, ordered by priority and then by first appearance.
  - Edits count distinct paths.
  - The rest become a remainder clause.
  - Clauses take the continuative form, joined with 「、」, and the last clause takes the final form.
- **Labels and status:** entry labels name what a call touched. Status text covers duration, 失敗, 終了コード N, 承認待ち or 承認が必要でした, スキップ, and 結果不明.

### Task 5: `Timeline` (Platform, TDD)

- **Structure:**
  - Rows, hidden tool rows included, place each record's work after the record's last row.
  - Turns start at the page's turn starts, and at user rows from outside the page (local sends and queued inputs).
- **Turn states:**
  - A settled turn folds everything before its final answer, plus finished work after it. People, images, the final answer, and later failures stay outside the fold.
  - A running turn shows its work inline, with a live trailing group.
  - A failed run lists every call.
  - A turn without tools, or a thread without a work log, looks as before.

### Task 6: Wiring and views

- **`AppModel`:**
  - It exposes `transcriptRows`, `selectedWorkLog`, and `activeRunID`.
  - It projects history and older pages.
  - It drops the work log with the connection.
- **`TranscriptView`:** renders `Timeline.build`, and each thread opens collapsed.

### Task 7: Demo and proof

- **Demo:**
  - A demo send records a test run, a read, and an edit with a numbered diff.
  - The team thread holds a failing test and a fix, 30 seconds after the prompt.
- **Proof:**
  - `just test`, `just lint`, `just build`, and `just uitest` pass.
  - The team-thread UI test opens the fold, the group, and the failing command's output.
  - The send UI test sees a fold after the reply.
  - Both UI tests fail on the old transcript.
